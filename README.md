# modm-data tools

Tools that use the data generated by [modm-data](https://github.com/modm-io/modm-data):
modm-data generates the data in a stable format, the tools here only read it.

- `modm_data_tools.lookup`: answers about STM32 devices (CMSIS headers, registers,
  documentation, figures, clock trees, interrupts) as a command line and as an MCP
  server for coding agents. Both offer the same functions.
- `modm_data_tools.clocks`: the clock solver and the modm SystemClock code generator,
  shared by the `clock_solve` lookup and the clock solver page.
- `web/`: the interactive pages of [data.modm.dev](https://data.modm.dev).

## Installation

The lookups read the data in the `ext/` folder of a modm-data checkout, so install
modm-data from that checkout, then these tools:

```sh
git clone https://github.com/modm-io/modm-data.git ../modm-data
make venv  # .venv with both editable, MODM_DATA=../modm-data by default
```

Most data comes from public sources that modm-data downloads with `make` (see its README).
The documentation and the CubeMX database are not redistributable: download the PDFs and
convert them with modm-data yourself.

## Lookups

Every lookup is a function that takes and returns text, available as a command:

```sh
modm-data-lookup --help
modm-data-lookup device_header g474re
modm-data-lookup decode_register stm32g474re --register RCC.CR --value 0x03030500
modm-data-lookup doc_table DS12288 13 --columns port,AF7 --where '^PA9$'
modm-data-lookup clock_solve STM32G474RETx "SYSCLK=max, FDCAN1=40M" --config "HSE=24M" --code
```

and as an MCP server with the same tools, over stdio for one client:

```sh
claude mcp add --scope user modm-data -- /path/to/modm-data-tools/.venv/bin/modm-data-mcp
```

or over HTTP for all clients, restarted whenever the code of the tools or of modm-data changes:

```sh
make mcp  # http://127.0.0.1:8765/mcp
claude mcp add --scope user --transport http modm-data http://127.0.0.1:8765/mcp
```

## Web Pages

| Page | Source | Data |
|------|--------|------|
| [SVD Register Explorer](https://data.modm.dev/svd/) | `web/svd/` | `python -m modm_data.header2svd.stmicro` |
| [Peripheral Variants](https://data.modm.dev/variants/) | `web/variants/` | `python -m modm_data.svd2variants` |
| [Board Pinouts](https://data.modm.dev/boards/) | `web/boards/` | `python -m modm_data.html2pinout` |
| [Pin Mapping](https://data.modm.dev/pinout/) | `web/pinout/`, `templates/pinout/` | `python -m modm_data.pinout --templates templates/pinout` |
| [Clock Solver](https://data.modm.dev/clocks/) | `web/clocks/` | `python -m modm_data.clocks`, then `python -m modm_data_tools.clocks.export` |

The pages are plain HTML, CSS and JavaScript without a build step. `web/` has the
layout of the homepage, and `make build-homepage` in modm-data copies the pages over
the data it generated. The clock solver page runs `modm_data.clocks` and
`modm_data_tools.clocks` in Pyodide, `export` copies that code next to the page.

To work on a page, generate its data in the modm-data checkout and serve the pages on
top of it, pages in `web/` take precedence:

```sh
make serve  # http://127.0.0.1:8768, data from ../modm-data/docs/src
```
